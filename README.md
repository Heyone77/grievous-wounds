# Тяжёлые ранения — Grim Hollow, 0.3.1

Модуль для **Foundry VTT v14, dnd5e 6.x**. Правила сверены с предоставленным PDF Grim Hollow Campaign Guide (Transformed), стр. 288-290 книги (292-294 PDF). Иллюстрации и сканы в модуль не включены.

## Установка

1. В Foundry откройте **Настройка → Дополнительные модули → Установить модуль**.
2. Вставьте в поле **Manifest URL**:

   `https://github.com/Heyone77/grievous-wounds/releases/latest/download/module.json`

3. Нажмите «Установить» и включите «Тяжёлые ранения - Grim Hollow» в мире.
4. Нужен включённый **libWrapper**. Для вашего набора оставьте включёнными **Midi-QOL, DAE, Coven's Automation Toolkit (CAT)** и CPR. CPR не является обязательной зависимостью.
5. Откройте меню заголовка листа персонажа → «Ранения». Альтернативный способ - Script-макрос:

```js
await game.modules.get("grievous-wounds").api.open();
```

В архиве есть `open-wounds-macro.json`: его можно импортировать как макрос Foundry. Сначала выберите токен; без выбранного токена откроется выбор персонажа.

**Обновления:** в настройке Foundry на вкладке модулей нажимайте «Проверить обновления». Foundry скачивает последний опубликованный релиз. Изменения в ветке GitHub становятся обновлением только после выпуска новой версии.

**Переход с установки папкой:** один раз установите текущий релиз по Manifest URL. Если Foundry не заменяет существующую папку, остановите сервер и замените `Data/modules/grievous-wounds` папкой из архива релиза. ID модуля остаётся `grievous-wounds`; записи ран хранятся в мире. Сделайте обычную резервную копию мира перед обновлением.

Для ручной установки скачайте `grievous-wounds.zip` из [последнего релиза](https://github.com/Heyone77/grievous-wounds/releases/latest) и распакуйте в `Data/modules/`.

## Ваше домашнее правило

При переходе **с положительных HP до 0** активный мастер отправляет окно активному владельцу персонажа:

- **Упасть:** остаётся 0 HP, новая рана не добавляется.
- **Принять рану:** бросок 2d10 с вычитанием накопленных тяжёлых ран, применение результата и 1 HP.

Если владельцев несколько, приоритет у пользователя, у которого этот персонаж выбран основным. Если игрока нет онлайн, окно получает мастер. Автоматическое предложение работает только для Actor типа `character`; ручное управление доступно через API.

### Выбор непосредственно перед записью HP (0.2.0)

Настройка **«Midi-QOL: выбор до применения 0 HP»** включена по умолчанию. Когда мастер применяет урон по пути Midi/dnd5e, синхронный хук `dnd5e.preApplyDamage` передаёт рассчитанную величину урона в ожидаемую обёртку `Actor.update`. Выбор появляется перед записью HP, когда сопротивления, спасброски и реакции уже учтены. Сам урон и исходные броски не перебрасываются.

- **Упасть:** применяется 0 HP и штатные последствия падения, прекращается концентрация. Каждая активная «Тяжёлая рана» добавляет провал спасброска от смерти.
- **Принять рану:** применяется ранение и сразу 1 HP. Персонаж не проходит через 0 HP; новая бессознательность и распластанность от падения не возникают. Ранее существовавшие состояния сохраняются. Если рана снижает максимум HP до 0, получить 1 HP невозможно.
- **На волосок:** 1 HP и распластанность без постоянной записи раны.
- **Сотрясение / смертельная рана:** концентрация прекращается. Смертельная рана даёт 0 HP и смерть.

После обычной раны концентрация проверяется один раз от полного рассчитанного урона, а не от разницы HP до и после выбора. СЛ рассчитывает `actor.getConcentrationDC`; сохраняются штатные бонусы и помехи. Для режима проверки Midi `item` используется `MidiQOL.doConcentrationCheck`, для остальных включённых режимов - штатный `rollConcentration`. Отключение концентрационных проверок или явный запрет проверки в исходных options уважаются. Незавершённая проверка требует ручного завершения; уже применённые урон и рана не применяются повторно из-за её отмены.

Пока открыто окно, обновление HP ожидает ответа. Закрытие окна игроком передаёт выбор мастеру. Закрытие окна мастером приостанавливает применение до изменения HP. В панели появляется сохранённая операция; продолжите её кнопкой «Продолжить выбор». Уже применённый урон по другим целям этим не отменяется. Бросок ранения сохраняется до завершения обновления; при повторной попытке того же обновления повторного броска и дублирования раны нет. Другое повреждение или изменение HP при незавершённом ранении требует разбора мастером.

**Границы:** ранняя обработка требует, чтобы окончательный `Actor.update` выполнялся мастером и получил метаданные из `dnd5e.preApplyDamage`. Прямые правки HP, массовый `Actor.updateDocuments`, нестандартные макросы и применение на клиенте игрока используют прежний путь после 0 HP. Для согласованного отката используйте «Журнал исходов» → «Отменить исход». Если карточка Midi сохранила ID события, возврат HP через неё распознаётся и последующая отмена раны не восстанавливает HP повторно. Точная установленная версия Midi-QOL 14.6.0 в этой среде не запускалась; интеграция сверена с опубликованными исходниками ветки v14 и имитацией API. Требуется проверка в вашем мире.

### Резервный выбор после 0 HP

Для остальных обновлений сначала применяется 0 HP. **Разрешите выбор до следующих действий, урона и спасбросков от смерти этого персонажа.** До падения запоминаются бессознательность (`unconscious`) и распластанность (`prone`). «Упасть» сохраняет последствия падения; обычная рана снимает только новые бессознательность и распластанность. «На волосок» сохраняет распластанность. Концентрация, уже прекращённая при 0 HP, не восстанавливается.

В резервном пути закрытие окна откладывает выбор. Мастер может повторить запрос или выбрать исход в окне ранений. Решение и бросок хранятся у персонажа. Лечение отменяет старый выбор; изменение спасбросков от смерти останавливает автоматическое разрешение для ручного разбора.

Результат **«Смертельная рана»** приводит к смерти, несмотря на домашнее правило 1 HP. Уже отмеченная смерть не отменяется выбором раны. Мгновенную смерть, нестандартные способы избежать 0 HP и взаимодействия со сторонними feature-макросами мастер должен проверять отдельно.

## Панель, журнал и отмена (0.3.0)

Окно показывает группы одинаковых ран с кратким суммарным последствием. Например, «Внутреннее кровотечение ×2» на уровне 5 показывает -30 максимальных HP. Описание и ID каждого экземпляра раскрываются по нажатию. Кнопка «Удалить рану» позволяет выбрать конкретный экземпляр по ID. Отключённые эффекты показаны отдельно и не входят в цену выбора.

До выбора выводятся добавляемые провалы спасброска от смерти, итог из трёх и предупреждение о смерти. Рядом показана формула 2d10 минус активные тяжёлые раны.

**Журнал исходов** хранит источник, величину урона, ID, решение, исходные результаты бросков и полученную рану. Поддерживаемая строка урона Midi связана с отдельным событием: повторное применение того же ID пропускается, включая повтор «Упасть» на уже нулевых HP. Новая независимая атака с тем же уроном получает другой ID. Последние 100 завершённых записей доступны подробно; незавершённые сохраняются независимо от лимита. Отдельные отметки уже обработанных ID не обрезаются вместе с подробным журналом. Если сторонний макрос не передаёт идентификатор события, одинаковые цифры урона сами по себе не считаются одним событием.

**Продолжить выбор** разрешает сохранённую операцию, в том числе после перезагрузки. Уже сделанный бросок и созданная рана не повторяются. Если HP уже записаны, завершаются оставшиеся последствия без повторного урона. Во время живого окна панель может передать решение в ту же операцию; поздний ответ из старого окна не меняет результат. После перезагрузки продолжение вызывает запись Actor и завершает действия этого модуля; исходные внешние макросы и остальные стадии workflow Midi повторно не запускаются. Старые сохранения 0.2.0 без данных для воспроизведения автоматически не угадываются.

**Отменить исход** сначала показывает конкретный план: HP/временные HP/tempmax, спасброски смерти, истощение, удаляемые раны с ID и изменения состояний. Подтверждение применяется только к этому событию. Последующие урон, лечение, изменения ран или механики эффекта останавливают отмену. Даже возврат HP к прежнему числу после другого урона не считается доказательством отсутствия изменений. Если HP уже возвращены поддерживаемой отменой Midi с тем же ID, повторного восстановления нет. Общий эффект сохраняет остальные состояния и механические изменения. Прерванную отмену можно продолжить из журнала, если состояние не менялось. Концентрация, эффекты заклинаний, потраченные ресурсы и внешние макросы автоматически не восстанавливаются.

**Снять зависший выбор** снимает только ожидание: текущие HP, раны, состояния и истощение остаются как есть. Это отдельное подтверждаемое действие для ручного разбора неоднозначных ситуаций. Оно доступно также в журнале для незавершённой записи. Полностью отменённый или снятый ID не применяется снова; для нового нанесения нужна новая операция.

**Проверить старые раны** предлагает исправления с предпросмотром. Дубли «Старой боли» идут вниз по постоянной таблице. Устаревшие описание/версия записи обновляются без повторного применения истощения и других последствий. «На волосок», ошибочно записанное как рана, теряет только запись в счётчике; состояния сохраняются. Неизвестные записи и дубли с неоднозначными состояниями/механикой остаются для ручного разбора. Никаких исправлений при открытии панели или загрузке мира не выполняется.

Пока есть незавершённый исход или его отмена, ручное добавление/удаление и лечение ран через панель заблокированы до завершения или явного снятия этой операции. Автоматизация рук, протезов и запрета Рывка в эту версию не добавлялась.

## Интеграция CAT / Midi-QOL / CPR

При активном CAT используется `cat.utils.effectUtils.createEffects` для создания эффектов и `cat.utils.rollUtils.addToRoll` для уменьшения уже брошенного урона. Штраф не перебрасывает исходные кости и не удваивается на критическом попадании. Обработчик `midi-qol.DamageRollComplete` вызывается в ожидаемой Midi асинхронной точке. После перерасчёта вызывается `workflow.setDamageRolls`.

Если атака наносит несколько типов урона, штраф сначала вычитается из первого компонента, затем из следующих; суммарный урон не становится отрицательным. Это соглашение реализации: страницы не уточняют распределение штрафа по типам урона. При неподдерживаемом workflow используйте ручной бросок штрафа в окне ранений; уже применённый автоматический штраф повторно вычитать нельзя. Настройка автоматического штрафа отключается отдельно.

Модуль не изменяет предметы и макросы CPR и не требует добавлять автоматизацию на каждое оружие. Конкретная комбинация установленных версий CAT, CPR, Midi и DAE требует проверки внутри вашего мира.

## Где участвует мастер

- Выбор повреждённой руки, запреты оружия/щита/соматических компонентов и действия повреждённым запястьем.
- Запрет Рывка при повреждённой/потерянной ноге, а также фактическое движение токена. Точные соглашения для метрической сетки лучше проверить в мире.
- Зрительные проверки при потере глаза: помеха не применяется ко всем проверкам Восприятия/Расследования без разбора.
- Приступы головокружения: взаимоисключение действия и бонусного действия в нечётные раунды.
- **Прилив адреналина:** критические попадания на 19–20 вне Bloodied и обычный урон критов в Bloodied. Здесь выведено описание, автоматическое изменение критов не заявлено.
- Назначение спасброска для Нерешительности: пока срабатывание доступно, после каждой карточки спасброска мастер получает вопрос, был ли он против испуга. «Нет» или закрытие окна сохраняет срабатывание. Источник и прекращение испуга также определяет мастер.
- Списание использования набора лекаря; мастер подтверждает наличие и расход. Персонажа-лекаря можно выбрать в окне лечения.
- Постоянные раны: после Regenerate удалите нужную рану через окно. Протез может компенсировать эффект: мастер может отключить соответствующий эффект. Автоматического распознавания Regenerate/протезов нет.
- Внешние макросы, которые обходят штатные методы лечения/концентрации/отдыха, могут требовать адаптации.
- «Избит» добавляет обычное истощение. Снятие записи раны не пытается вычислить и удалить истощение, полученное из разных источников; остаток истощения при лечении проверяется вручную.

## Настройки и соглашения

В настройках мира можно отключить автоматический выбор при 0 HP, ранний выбор перед записью HP и автоматический штраф надрыва мышцы. Постоянные раны не учитываются в штрафе к 2d10 и СЛ лечения. Старая настройка `permanentCount` больше не используется, в том числе в существующих мирах.

Отключённые эффекты ран не дают механики и не учитываются в числе активных ран. Результат «На волосок» не сохраняется как рана. Число повторных повреждений ноги учитывается, но штраф -10 футов не суммируется. Результат надрыва после пятого заменяется повреждённой ногой.

Лечение предоставляет **одну попытку за завершённый долгий отдых**, в том числе при провале проверки. Страницы не расписывают повторные попытки; это явное соглашение этой сборки. Для административного исправления можно удалить рану вручную.

Для Dazed и Bleeding предусмотрены свои статусные метки. Необязательно укажите в настройках ID состояния другого модуля. Независимо от выбранной метки ограничения концентрации и восстановления HP выполняет этот модуль. Новое состояние Corruption с третьей страницы не входит в таблицы ранений и отдельно не реализовано.

## Проверка в мире перед использованием

Создайте тестового персонажа и отдельного игрока-владельца. Проверьте:

1. С положительных HP примените урон до 0. Игрок должен получить окно выбора. Выберите падение: нового эффекта раны быть не должно.
2. Восстановите HP, снова нанесите урон до 0 и выберите ранение: бросок, эффект и 1 HP, кроме смертельного исхода. Проверьте, что Midi не возвращает бессознательность после закрытия окна.
3. Вручную добавьте сотрясение, затем попробуйте концентрироваться. Добавьте глубокий порез: обычное лечение блокируется, кости хитов работают; завершите короткий отдых и проверьте исчезновение только кровотечения.
4. Добавьте надрыв мышцы и атакуйте оружием через Midi: штраф должен появиться один раз и уже быть вычтен. Проверьте критический урон и вашу конкретную безоружную атаку.
5. Проверьте помехи на спасброски, лечение после долгого отдыха и повторный запрос отложенного выбора.
6. Начните концентрацию на тестовом персонаже с игроком-владельцем. Нанесите урон через Midi до 0 HP: до ответа HP не должны меняться. При обычной ране должно стать сразу 1 HP, а концентрация должна требовать одну проверку от полного урона. Проверьте успех и провал, а также урон при исходных 1 HP и при наличии временных HP.
7. Проверьте «Упасть», сотрясение, смертельный результат и «На волосок». Закройте окно игрока (выбор у мастера), затем окно мастера и продолжите из панели. Ручная правка HP до 0 должна вызывать резервный выбор после падения.
8. Проверьте журнал, повторное нажатие одной строки урона и новую независимую атаку тем же оружием с тем же уроном. Отмените последний исход из журнала; отдельно проверьте отмену после возврата HP карточкой Midi. Нанесите новый урон или измените истощение и убедитесь, что старый исход не откатывает более поздние изменения.
9. На копии персонажа создайте дубль «Старой боли». Предпросмотр проверки должен предложить «Нерешительность», а закрытие подтверждения не должно менять данные. Проверьте удаление одного экземпляра из компактной группы.

**Статус проверки:** синтаксис JavaScript и 120 автоматизированных тестов правил/логики с имитацией API пройдены. Запуска настоящего Foundry и проверки по сети GM↔игрок в этой среде не было; версия 0.3.0 является сборкой для проверки в вашем мире.

## Изменения 0.1.3

- При переходе на 0 HP сохраняются состояния бессознательности и распластанности до падения.
- «Упасть» сохраняет последствия падения; «Принять рану» снимает только новые состояния бессознательности и распластанности. Ранее существовавшие состояния сохраняются.
- «На волосок» сохраняет 1 HP и распластанность по таблице. Смертельный результат не очищает последствия падения.
- Если один эффект содержит несколько состояний или другие механические изменения, очистка сохраняет остальные состояния и изменения.
- Незавершённые выборы из старых версий не содержат снимка распластанности, поэтому она сохраняется для ручной проверки мастером.

## Изменения 0.1.2

Окно ранений ограничено высотой экрана. Длинный список прокручивается внутри окна, а кнопки остаются в отдельной нижней области и переносятся на несколько строк.

## Изменения 0.1.1

- Повторы неповторяемых постоянных ран переходят к следующему меньшему доступному результату без переброса. Например, повторная «Старая боль» (10) даёт «Нерешительность» (9), если её ещё нет. Применено общее правило повторов со стр. 288 к обеим таблицам: в постоянной таблице стр. 289 звёздочкой отмечены рука, нога и глаз. Отдельного повторения этого правила в разделе постоянных ран нет.
- Ручное добавление уже активной неповторяемой раны отклоняется с сообщением. Отключённые эффекты не блокируют новый результат.
- Внутреннее кровотечение допускает повтор, каждый экземпляр уменьшает максимум HP на 3 × уровень.
- Повторная потеря ноги уменьшает скорость ещё на 15 футов, минимум до 5 футов.
- Нерешительность применяется только к спасброску против испуга с подтверждением мастера.
- Штраф к 2d10 и СЛ лечения учитывают только тяжёлые раны.

Существующие эффекты в мире автоматически не заменяются. Для исправления уже созданного дубля «Старой боли» удалите один экземпляр и добавьте «Нерешительность» вручную; если она уже есть, выберите следующий меньший доступный результат по таблице. Описания ранее созданных эффектов также могут содержать старый текст; окно «Ранения» показывает актуальные правила.

## API

```js
const wounds = game.modules.get("grievous-wounds").api;
await wounds.open();                         // Окно выбранного токена
await wounds.open(actor);                    // Окно конкретного Actor
await wounds.rollWound(actor);               // GM: бросить/применить рану, без сценария 0 HP
await wounds.addWound(actor, "grievous", 8);  // GM: глубокий порез
await wounds.addWound(actor, "permanent", 6); // GM: повреждённые лёгкие
await wounds.requestChoice(actor);           // GM: повторить отложенный выбор
await wounds.treat(actor);                   // GM: лечение после отдыха
await wounds.openJournal(actor);             // Журнал и подтверждаемая отмена
await wounds.resumeDamage(actor);            // GM: продолжить ранний выбор
const events = wounds.eventLog(actor);
const plan = wounds.undoPreview(actor, events.at(-1).id); // Только предпросмотр
// API-вызовы ниже изменяют данные без собственного диалога подтверждения:
await wounds.undoEvent(actor, plan.event.id); // GM: применить проверенный план отмены
const issues = wounds.auditWounds(actor);     // Только список предлагаемых исправлений
const repair = wounds.repairPreview(actor, issues[0].effectId);
await wounds.repairWound(actor, repair.effectId, {expected: repair});
await wounds.abandonDamage(actor);           // GM: снять ожидание, сохранить текущее состояние
console.table(wounds.records(actor));
```

Проверки для разработчика: `node --test tests/*.test.mjs`.

## Выпуск версии

Требуются Node.js 22+, Python 3 и Git. Зависимостей npm нет.

1. Измените `version` в `module.json` и `package.json`, а также версию тега в `module.json.download`. URL `manifest` остаётся постоянным.
2. Обновите описание изменений в README. Запустите `npm test` и `npm run build`.
3. Сохраните изменения коммитом и отправьте ветку. Создайте тег, совпадающий с версией: например, `git tag v0.3.2`, затем `git push origin v0.3.2`.
4. Workflow Release проверит тесты, соберёт архив из разрешённого списка файлов, загрузит ZIP и манифест в черновик релиза, затем опубликует его. При ошибке черновик не становится обновлением.

Готовые файлы появляются в `output/release/`. PDF, тесты, служебные файлы и история Git в установочный архив не входят. Сборка проверяет совпадение версии тега, пакета и манифеста, URL загрузки, состав архива и копии файлов.
