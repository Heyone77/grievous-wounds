# Тяжёлые ранения — Grim Hollow, 0.2.0

Модуль для **Foundry VTT v14, dnd5e 6.x**. Правила сверены с предоставленным PDF Grim Hollow Campaign Guide (Transformed), стр. 288-290 книги (292-294 PDF). Иллюстрации и сканы в модуль не включены.

## Установка

1. Распакуйте архив. Папка `grievous-wounds` должна находиться в `Data/modules/`, а `module.json` — прямо внутри неё.
2. Перезапустите Foundry и включите модуль «Тяжёлые ранения — Grim Hollow» в мире.
3. Нужен включённый **libWrapper**. Для вашего набора оставьте включёнными **Midi-QOL, DAE, Coven's Automation Toolkit (CAT)** и CPR. CPR не является обязательной зависимостью.
4. Откройте меню заголовка листа персонажа → «Ранения». Альтернативный способ: создайте Script-макрос:

```js
await game.modules.get("grievous-wounds").api.open();
```

В архиве есть `open-wounds-macro.json`: его можно импортировать как макрос Foundry. Сначала выберите токен; без выбранного токена откроется выбор персонажа.

Публичного URL манифеста у этой локальной сборки нет; устанавливайте папкой, а не через поле Manifest URL.

## Ваше домашнее правило

При переходе **с положительных HP до 0** активный мастер отправляет окно активному владельцу персонажа:

- **Упасть:** остаётся 0 HP, новая рана не добавляется.
- **Принять рану:** бросок 2d10 с вычитанием накопленных тяжёлых ран, применение результата и 1 HP.

Если владельцев несколько, приоритет у пользователя, у которого этот персонаж выбран основным. Если игрока нет онлайн, окно получает мастер. Автоматическое предложение работает только для Actor типа `character`; ручное управление доступно через API.

### Выбор непосредственно перед записью HP (0.2.0)

Настройка **«Midi-QOL: выбор до применения 0 HP»** включена по умолчанию. Когда мастер применяет урон по пути Midi/dnd5e, синхронный хук `dnd5e.preApplyDamage` передаёт рассчитанную величину урона в ожидаемую обёртку `Actor.update`. Выбор появляется перед записью HP, когда сопротивления, спасброски и реакции уже учтены. Сам урон и исходные броски не перебрасываются.

- **Упасть:** применяется 0 HP и штатные последствия падения, прекращается концентрация. Каждая активная «Тяжёлая рана» добавляет провал спасброска от смерти.
- **Принять рану:** применяется ранение и сразу 1 HP. Персонаж не проходит через 0 HP; новая бессознательность и распластанность от падения не возникают. Ранее существовавшие состояния сохраняются. Если рана снижает максимум HP до 0, получить 1 HP невозможно.
- **На волосок:** 1 HP и распластанность без постоянной записи раны.
- **Сотрясение / смертельная рана:** концентрация прекращается. Смертельная рана даёт 0 HP и смерть.

После обычной раны концентрация проверяется один раз от полного рассчитанного урона, а не от разницы HP до и после выбора. СЛ рассчитывает `actor.getConcentrationDC`; сохраняются штатные бонусы и помехи. Для режима проверки Midi `item` используется `MidiQOL.doConcentrationCheck`, для остальных включённых режимов - штатный `rollConcentration`. Отключение концентрационных проверок или явный запрет проверки в исходных options уважаются. Незавершённая проверка требует ручного завершения; уже применённые урон и рана не применяются повторно из-за её отмены.

Пока открыто окно, обновление HP ожидает ответа. Закрытие окна игроком передаёт выбор мастеру. Закрытие окна мастером отменяет именно это применение урона до изменения HP; примените его повторно для продолжения. Уже применённый урон по другим целям этим не отменяется. Бросок ранения сохраняется до завершения обновления; при повторной попытке того же обновления повторного броска и дублирования раны нет. Другое повреждение или изменение HP при незавершённом ранении требует разбора мастером.

**Границы:** ранняя обработка требует, чтобы окончательный `Actor.update` выполнялся мастером и получил метаданные из `dnd5e.preApplyDamage`. Прямые правки HP, массовый `Actor.updateDocuments`, нестандартные макросы и применение на клиенте игрока используют прежний путь после 0 HP. Отмена урона через карточку Midi не обещает автоматического отката добавленной раны или её последствий; их мастер исправляет отдельно. Точная установленная версия Midi-QOL 14.6.0 в этой среде не запускалась; интеграция сверена с опубликованными исходниками ветки v14 и имитацией API. Требуется проверка в вашем мире.

### Резервный выбор после 0 HP

Для остальных обновлений сначала применяется 0 HP. **Разрешите выбор до следующих действий, урона и спасбросков от смерти этого персонажа.** До падения запоминаются бессознательность (`unconscious`) и распластанность (`prone`). «Упасть» сохраняет последствия падения; обычная рана снимает только новые бессознательность и распластанность. «На волосок» сохраняет распластанность. Концентрация, уже прекращённая при 0 HP, не восстанавливается.

В резервном пути закрытие окна откладывает выбор. Мастер может повторить запрос или выбрать исход в окне ранений. Решение и бросок хранятся у персонажа. Лечение отменяет старый выбор; изменение спасбросков от смерти останавливает автоматическое разрешение для ручного разбора.

Результат **«Смертельная рана»** приводит к смерти, несмотря на домашнее правило 1 HP. Уже отмеченная смерть не отменяется выбором раны. Мгновенную смерть, нестандартные способы избежать 0 HP и взаимодействия со сторонними feature-макросами мастер должен проверять отдельно.

## Интеграция CAT / Midi-QOL / CPR

При активном CAT используется `cat.utils.effectUtils.createEffects` для создания эффектов и `cat.utils.rollUtils.addToRoll` для уменьшения уже брошенного урона. Штраф не перебрасывает исходные кости и не удваивается на критическом попадании. Обработчик `midi-qol.DamageRollComplete` вызывается в ожидаемой Midi асинхронной точке. После перерасчёта вызывается `workflow.setDamageRolls`.

Если атака наносит несколько типов урона, штраф сначала вычитается из первого компонента, затем из следующих; суммарный урон не становится отрицательным. Это соглашение реализации: страницы не уточняют распределение штрафа по типам урона. При неподдерживаемом workflow используйте ручной бросок штрафа в окне ранений; уже применённый автоматический штраф повторно вычитать нельзя. Настройка автоматического штрафа отключается отдельно.

Модуль не изменяет предметы и макросы CPR и не требует добавлять автоматизацию на каждое оружие. Конкретная комбинация установленных версий CAT, CPR, Midi и DAE требует проверки внутри вашего мира.

## Где участвует мастер

- Выбор повреждённой руки, запреты оружия/щита/соматических компонентов и действия повреждённым запястьем.
- Запрет Рывка при повреждённой/потерянной ноге, а также фактическое движение токена. Точные соглашения для метрической сетки лучше проверить в мире.
- Зрительные проверки при потере глаза: помеха не применяется ко всем проверкам Восприятия/Расследования без разбора.
- Приступы головокружения: взаимоисключение действия и бонусного действия в нечётные раунды.
- **Прилив адреналина:** критические попадания на 19–20 вне Bloodied и обычный урон критов в Bloodied. Здесь выведено описание, автоматическое изменение критов не заявлено.
- Назначение спасброска для Нерешительности: пока срабатывание доступно, после каждой карточки спасброска мастер получает вопрос, был ли он против испуга. «Нет» или закрытие окна сохраняет срабатывание. Источник и прекращение испуга также определяет мастер.
- Списание использования набора лекаря; мастер подтверждает наличие и расход. Персонажа-лекаря можно выбрать в окне лечения.
- Постоянные раны: после Regenerate удалите нужную рану через окно. Протез может компенсировать эффект: мастер может отключить соответствующий эффект. Автоматического распознавания Regenerate/протезов нет.
- Внешние макросы, которые обходят штатные методы лечения/концентрации/отдыха, могут требовать адаптации.
- «Избит» добавляет обычное истощение. Снятие записи раны не пытается вычислить и удалить истощение, полученное из разных источников; остаток истощения при лечении проверяется вручную.

## Настройки и соглашения

В настройках мира можно отключить автоматический выбор при 0 HP, ранний выбор перед записью HP и автоматический штраф надрыва мышцы. Постоянные раны не учитываются в штрафе к 2d10 и СЛ лечения. Старая настройка `permanentCount` больше не используется, в том числе в существующих мирах.

Отключённые эффекты ран не дают механики и не учитываются в числе активных ран. Результат «На волосок» не сохраняется как рана. Число повторных повреждений ноги учитывается, но штраф -10 футов не суммируется. Результат надрыва после пятого заменяется повреждённой ногой.

Лечение предоставляет **одну попытку за завершённый долгий отдых**, в том числе при провале проверки. Страницы не расписывают повторные попытки; это явное соглашение этой сборки. Для административного исправления можно удалить рану вручную.

Для Dazed и Bleeding предусмотрены свои статусные метки. Необязательно укажите в настройках ID состояния другого модуля. Независимо от выбранной метки ограничения концентрации и восстановления HP выполняет этот модуль. Новое состояние Corruption с третьей страницы не входит в таблицы ранений и отдельно не реализовано.

## Проверка в мире перед использованием

Создайте тестового персонажа и отдельного игрока-владельца. Проверьте:

1. С положительных HP примените урон до 0. Игрок должен получить окно выбора. Выберите падение: нового эффекта раны быть не должно.
2. Восстановите HP, снова нанесите урон до 0 и выберите ранение: бросок, эффект и 1 HP, кроме смертельного исхода. Проверьте, что Midi не возвращает бессознательность после закрытия окна.
3. Вручную добавьте сотрясение, затем попробуйте концентрироваться. Добавьте глубокий порез: обычное лечение блокируется, кости хитов работают; завершите короткий отдых и проверьте исчезновение только кровотечения.
4. Добавьте надрыв мышцы и атакуйте оружием через Midi: штраф должен появиться один раз и уже быть вычтен. Проверьте критический урон и вашу конкретную безоружную атаку.
5. Проверьте помехи на спасброски, лечение после долгого отдыха и повторный запрос отложенного выбора.
6. Начните концентрацию на тестовом персонаже с игроком-владельцем. Нанесите урон через Midi до 0 HP: до ответа HP не должны меняться. При обычной ране должно стать сразу 1 HP, а концентрация должна требовать одну проверку от полного урона. Проверьте успех и провал, а также урон при исходных 1 HP и при наличии временных HP.
7. Проверьте «Упасть», сотрясение, смертельный результат и «На волосок». Проверьте закрытие окна игроком (выбор у мастера) и мастером (урон ещё не применён). Ручная правка HP до 0 должна вызывать резервный выбор после падения.

**Статус проверки:** синтаксис JavaScript и 71 автоматизированный тест правил/логики с имитацией API пройдены. Запуска настоящего Foundry и проверки по сети GM↔игрок в этой среде не было; версия 0.2.0 является сборкой для проверки в вашем мире.

## Изменения 0.1.3

Существующие эффекты в мире автоматически не заменяются. Для исправления уже созданного дубля «Старой боли» удалите один экземпляр и добавьте «Нерешительность» вручную; если она уже есть, выберите следующий меньший доступный результат по таблице. Описания ранее созданных эффектов также могут содержать старый текст; окно «Ранения» показывает актуальные правила.

## API

```js
const wounds = game.modules.get("grievous-wounds").api;
await wounds.open();                         // Окно выбранного токена
await wounds.open(actor);                    // Окно конкретного Actor
await wounds.rollWound(actor);               // GM: бросить/применить рану, без сценария 0 HP
await wounds.addWound(actor, "grievous", 8);  // GM: глубокий порез
```
