# Исправление подготовки акторов в 0.3.2

Целевое окружение: Foundry 14.370, dnd5e 6.0.6, libWrapper, DAE и Midi-QOL.
Версия 0.3.2 подготовлена для выпуска через GitHub Releases. На сервер она автоматически не устанавливается; проверка в живом Foundry остаётся за владельцем мира.

## Подтверждённая причина

В 0.3.1 обёртка Actor.prepareData регистрировалась в setup, а ready повторно вызывал prepareData для всех акторов мира и токенов текущей сцены. По документации Foundry v14 setup происходит уже после инициализации документов. Обходной повтор в ready запускал подготовку поверх существующей модели, без её восстановления из исходных данных.

В официальном теге dnd5e release-6.0.6:

- CharacterData.prepareBaseData и NPCData.prepareBaseData прибавляют уровни классов к details.level через +=.
- CommonTemplate.shimBonusData вызывает Object.defineProperty для attributes.concentration.bonuses.save и других старых путей. У getter нет configurable:true, поэтому определить его повторно на том же контейнере нельзя.
- Уровень увеличивается до вызова shimBonusData. Поэтому ошибка оставляет частично подготовленную модель: друид 3-го уровня уже стал 6-го, а проход завершился исключением.

Выполнены настоящие методы prepareBaseData и shimBonusData из загруженных официальных файлов. Для остальных зависимостей использованы заглушки: Foundry целиком не запускался. Получен результат:

```text
character first preparation: 3 configurable save: false
character second preparation: 6 TypeError: Cannot redefine property: save
npc first preparation: 3 configurable save: false
npc second preparation: 6 TypeError: Cannot redefine property: save
```

Указание DAE в стеке согласуется с его опубликованной веткой v14: DAE оборачивает prepareData через libWrapper и ловит исключения подготовки, выводя их в консоль. Точная установленная версия DAE не была доступна. Причина воспроизводится без DAE и Midi; это не доказательство отдельной ошибки в них. Исправление не сбрасывает вручную уровень и не меняет шима системы.

## Изменение

Обёртка подготовки ранений регистрируется в init, до первоначальной подготовки документов. Она один раз вызывает wrapped с исходными аргументами и this, затем применяет вычисляемые штрафы и возвращает исходный результат. Цепочка libWrapper сохраняется. Обёртки update, _rest и initiateRest остаются в setup. Убрана принудительная подготовка в ready, публикация API и напоминание о незавершённом выборе сохранены.

Теперь ранения учитываются при первой подготовке, при загрузке акторов токенов и при штатном пересчёте после обновления актора или его эффектов. Обновления в базе из подготовки не выполняются. Полная перезагрузка после установки обязательна: уже повреждённая в памяти модель не ремонтируется на лету.

## Автоматические проверки и их пределы

`npm test`: 123 теста. До исправления новый тест ready падал с Cannot redefine property: save, со стеком через main.mjs:942 и main.mjs:958. Другой новый тест показывал отсутствие штрафа ранений при первой загрузке. После исправления оба проходят.

tests/preparation.test.mjs моделирует init -> подготовка документов -> setup -> ready, отдельно - сброс модели из source. Проверены персонаж, NPC, раненый персонаж, непривязанный актор токена, первая загрузка, повторные штатные пересчёты, изменение уровня/HP, отключение и удаление раны, исходные HP/скорость, API и напоминание. Дополнительная обёртка моделирует сторонние изменения максимума HP и скорости. Это проверка контракта цепочки, а не запуск настоящего DAE. Прежние тесты проверяют API Midi, выбор на 0 HP, концентрацию, журнал и отмену через имитацию окружения.

Для повторения диагностики на реальных методах сохраните официальные common.mjs, character.mjs и npc.mjs из тега release-6.0.6 в папку tmp/actor-preparation под именами common-6.0.6.mjs, character-6.0.6.mjs и npc-6.0.6.mjs. Затем выполните:

```text
node tests/diagnostics/dnd5e-606.mjs tmp/actor-preparation
```

Скрипт извлекает нужные методы из этих локальных файлов и выполняет их с узкими заглушками. Он не загружает файлы из сети и не включён в установочный архив. Не передавайте ему недоверенные исходники: он выполняет извлечённый JavaScript.

## Установка для проверки

Если модуль уже установлен через манифест GitHub, после публикации 0.3.2 обновите его на стартовом экране Foundry: «Дополнительные модули» -> «Проверить обновления». Затем полностью перезагрузите мир и браузер. Проверьте номер версии и выполните сценарии ниже начиная с пункта 3. Предварительно сохраните резервную копию мира и текущей папки модуля.

Альтернативная ручная установка:

1. Сохраните резервную копию мира и текущей папки модуля. Остановите сервер Foundry.
2. Распакуйте output/grievous-wounds-0.3.2.zip в Data/modules с заменой прежней папки grievous-wounds. Не создавайте вложенную папку grievous-wounds/grievous-wounds. В module.json должна быть версия 0.3.2.
3. Запустите сервер, полностью перезагрузите браузер и откройте копию мира с прежними DAE, Midi-QOL и libWrapper.
4. Проверьте консоль при загрузке и после нескольких правок персонажа: нет повторяющихся ошибок подготовки, уровень друида остаётся 3. Проверьте NPC и непривязанный токен, в том числе при смене сцены.
5. У персонажа с сохранённой раной сразу после загрузки проверьте максимум HP/скорость. Для внутреннего кровотечения на уровне 3 ожидается -9 HP, для повреждённых лёгких -3 HP, для потерянной ноги -15 футов с прежним нижним пределом. Учтите остальные эффекты DAE.
6. Измените уровень/класс, максимум HP; отключите, включите и удалите эффект раны. Проверьте, что штраф не накапливается и при удалении исчезает. Перезагрузите мир и проверьте повторно.
7. Через Midi нанесите урон до 0 HP: проверьте оба исхода, концентрацию и отмену последнего исхода. Проверьте короткий/долгий отдых и обычный эффект DAE, меняющий HP или скорость.

Эти проверки живого Foundry 14.370 с вашими версиями модулей автоматически не выполнены. Для отката остановите сервер, верните прежнюю папку и перезагрузите мир. Изменять уровни классов ради исправления отображения не нужно, если сами исходные данные не редактировались.
